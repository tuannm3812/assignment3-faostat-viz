# Assignment 3 - Part 3 Group Final Portfolio Instructions

## Project Brief

**The Data Narrative Studio** asks the group to act as a specialist data consultancy. The final product must transform complex, multi-dimensional, real-world data into an interactive and persuasive data narrative. The goal is not to build a generic status dashboard, but to create a human-centered story that invokes emotion, convinces with evidence, and drives a clear stakeholder action.

## Assessment Context

- **Weighting:** 40% total for Assignment 3.
- **Part 3 weighting:** 20%.
- **Format:** Group project, 7-8 members.
- **Tooling:** Tableau or Streamlit, GitHub, and SharePoint/Teams.
- **Submission:** File upload.
- **Part 3 due date:** Sunday, 17 May 2026, with automatic extension guidance noted by the teaching team.
- **Grading:** Shared group mark, moderated by observable contribution evidence if needed.

## Subject Intended Learning Outcomes

The project assesses the group's ability to:

- **SILO 1:** Justify the selection and analysis of data for stakeholder-specific data narratives.
- **SILO 2:** Apply visualisation and narrative techniques across varied data types.
- **SILO 3:** Justify narrative tools and techniques that illuminate critical aspects of a problem.
- **SILO 4:** Communicate data narratives to stakeholders using relevant patterns, analysis, and evidence.

## Rich Data Requirements

The final portfolio must use real-world, recent data. Synthetic or overused blacklisted datasets such as Titanic, Superstore, and Iris are not acceptable.

The data must:

- Be collected from 2024 onwards, or contain earlier data points from a source actively collected or updated in 2026.
- Include temporal variables, spatial variables, or both.
- Support at least four purposeful visuals.
- Ideally enrich or join multiple datasets to reveal stronger "So What" insights.

## Human-Centered Design Requirements

The dashboard must be designed for a specific audience and justified through user stories. The group should define:

- A clear stakeholder persona.
- User stories that explain what the stakeholder needs to understand or decide.
- Acceptance criteria and a definition of done.
- Visual design choices informed by Gestalt principles, pre-attentive attributes, and cognitive load reduction.
- Accessibility choices such as high colour contrast, readable layout, and intuitive affordances.

For this project, the chosen stakeholder persona is:

> **UN Food Systems Summit Panel or a regional food-security policy board.**

## Advanced Feature Requirement

The final dashboard must include at least three advanced features or tool-specific equivalents. Suitable Streamlit features include:

- **Context-aware filtering:** User selections update charts, rankings, metrics, or narrative text.
- **Visual tooltips or modals:** Hover states reveal deeper country, commodity, or methodology details.
- **Narrative scrollytelling or guided layout:** The interface leads users through a structured story.
- **What-if parameterisation:** Sliders or inputs allow users to model alternative scenario assumptions.

## Narrative Arc Options

Each group must choose and justify one narrative structure:

- **What -> So What -> What Next:** Executive story from evidence to implication to action.
- **Martini Glass:** Author-led narrative first, then user-driven exploration.
- **Detective:** Start with an anomaly and reveal the likely cause.
- **Sparkline:** Compare what is happening now with what could happen or what should happen.

This project uses a **Sparkline** narrative: global and producer-price shocks show "what is", while the exposure and what-if views show where action could reduce food-security risk.

## Part 3 Deliverables

The final portfolio must include:

- **Live dashboard:** Hosted on Streamlit Cloud or Tableau Public.
- **Technical polish:** Consistent design system, custom palette or Streamlit configuration, and responsive load times.
- **Video walkthrough:** A 3-minute tour explaining code logic or Tableau organisation and highlighting the three advanced features.
- **Technical documentation:** Data dictionary, source provenance, methodology, limitations, and credits in the README or equivalent documentation.
- **Annotated implementation:** Streamlit code should be clear and annotated where useful; Tableau worksheets should be logically named and organised.
- **Repository evidence:** GitHub should show organised code, data workflow, and contribution history.

## Collaboration Expectations

The group should operate as an integrated studio:

- **Code Track:** Developers and analysts manage Python files, data cleaning, GitHub, and deployment.
- **Design and Strategy Track:** Designers and presenters manage personas, branding, scripts, slides, and SharePoint/Teams evidence.
- **Accountability:** Shared marks may be moderated through GitHub, SharePoint, Teams version history, and peer evaluation if contribution imbalance is raised.

## What Our Final Dashboard Must Prove

For the UN or regional policy-board persona, the dashboard should help answer:

- When have global food prices and AUS/NZ producer-price signals intensified?
- Which commodities show the strongest or most volatile signals?
- Which countries combine hunger vulnerability with food-import dependency?
- Under alternative producer-price shock assumptions, which countries should be prioritised for monitoring, preparedness, or policy support?

The dashboard should make a clear recommendation: use hunger-import exposure as an early-warning layer when producer-price and global food-price signals rise together.
